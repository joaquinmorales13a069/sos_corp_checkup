# Diseño: ISO 27001 Fase 11 — Página de Política de Privacidad

> **Fecha:** 2026-05-07
> **Rama:** feat/seguridad
> **Estado:** Aprobado

---

## Alcance

Una sola página pública (`/politica-privacidad`) con:
- Política de privacidad y protección de datos
- Sección de seguridad ISO 27001 integrada

Descartado en este diseño:
- `/dashboard/admin/cumplimiento` — expone métodos de seguridad, redundante para el equipo admin
- `/aviso-cumplimiento` como página separada — contenido integrado en `/politica-privacidad`

---

## Arquitectura

### Ruta

```
/app/politica-privacidad/
  layout.tsx    ← Server Component, sin auth guard, monta PublicShell
  page.tsx      ← Server Component, contenido estático hardcodeado en TSX
```

### Componentes nuevos

```
/components/public/
  PublicShell.tsx    ← 'use client' — gestiona estado mobile sidebar + layout wrapper
  PublicSidebar.tsx  ← 'use client' — logo + link "Iniciar sesión", sin nav items
```

### Flujo

```
/app/politica-privacidad/layout.tsx
  └── <PublicShell>        (client, mobile sidebar state)
        ├── <PublicSidebar>  (logo + "Iniciar sesión" → /login)
        └── <main>
              └── {children}  ← page.tsx content
```

Sin `getUser()`, sin `redirect()`. Accesible sin sesión.

---

## PublicSidebar

Basada visualmente en `AdminSidebar` pero con:
- Logo SOS Medical (igual que AdminSidebar)
- Sin nav items (ninguna sección de Clientes/Chequeos/Cuenta)
- Sin botón de logout
- Un único link al fondo: **"Iniciar sesión"** → `/login`
- Mismo fondo `bg-surface-container-lowest` y ancho `w-[240px]`
- Botón hamburger en mobile (mismo patrón de `open`/`onClose` que `AdminSidebar`)

---

## PublicShell

Mismo patrón que `AdminShell` pero sin `AdminHeader`:
- Gestiona `sidebarOpen` state
- Overlay oscuro en mobile cuando sidebar está abierta
- `<main>` con `lg:ml-[240px]` y padding estándar

No tiene `AdminHeader`. En su lugar, `PublicShell` renderiza una barra superior sticky (`h-16`) solo visible en mobile (`lg:hidden`) que contiene el botón hamburger para abrir la sidebar. En desktop (`lg:`) esta barra no se muestra — la sidebar siempre está visible.

## Contenido de la página (`page.tsx`)

Texto estático en español, hardcodeado en el componente. Sin base de datos.

### Secciones

| # | Título | Contenido |
|---|--------|-----------|
| 1 | Responsable del tratamiento | SOS Medical Nicaragua como controlador de datos; datos de contacto |
| 2 | Datos que procesamos | Epicrisis de trabajadores (almacenadas en Google Drive); datos de acceso al sistema (email, nombre, rol) |
| 3 | Finalidad del tratamiento | Gestión de chequeos médicos empresariales; entrega de resultados a responsables asignados |
| 4 | Base legal | Relación contractual entre SOS Medical y las empresas cliente; consentimiento informado de los trabajadores |
| 5 | Flujo de datos | Admin SOS Medical → Google Drive → Responsable de empresa → Trabajador |
| 6 | Derechos de los titulares | Acceso, rectificación, supresión, oposición, portabilidad; contacto para ejercerlos |
| 7 | Retención de datos | Datos conservados mientras dure la relación contractual con la empresa cliente + período legal aplicable |
| 8 | Seguridad de la información | *"Este sistema fue desarrollado siguiendo las directrices de la norma ISO 27001, con el objetivo de garantizar la confidencialidad, integridad y disponibilidad de la información médica gestionada."* — tarjeta visualmente destacada |
| 9 | Contacto | `desarrollo@sosmedical.com.ni` — consultas sobre privacidad y tratamiento de datos |

### Estilo de las secciones

- Cada sección: tarjeta `bg-white border border-surface-container-high rounded-xl p-5`
- Título de sección: `text-primary font-semibold`
- Sección 8 (ISO): tarjeta con fondo `bg-primary-fixed` y borde `border-primary/20`, ícono de escudo, texto en negrita para "ISO 27001"
- Header de página: badge rojo "Política de Privacidad" + título H1 + fecha de última actualización
- Layout: columna única centrada, `max-w-3xl mx-auto`

## Lo que NO se incluye

- Ninguna mención a proveedores de infraestructura (Supabase, Contabo, Google)
- No se afirma que el sistema esté certificado ISO 27001 — solo que fue desarrollado siguiendo sus directrices
- Sin base de datos — todo el contenido es estático
- Sin `/dashboard/admin/cumplimiento`
