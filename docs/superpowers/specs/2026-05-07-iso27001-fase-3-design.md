### Gap a cerrar — Content-Security-Policy

Agregar a `next.config.ts` en `securityHeaders`:

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'unsafe-inline' 'unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: https://*.supabase.co;
  font-src 'self';
  connect-src 'self' https://*.supabase.co wss://*.supabase.co;
  frame-src 'none';
  object-src 'none';
  base-uri 'self';
  form-action 'self';
```

`unsafe-inline` y `unsafe-eval` en `script-src` son requeridos por Next.js 16 (scripts de hydración y chunk loading). Protecciones activas con esta CSP:
- `frame-src 'none'` — bloquea iframes de terceros (clickjacking layer 2, refuerza X-Frame-Options)
- `object-src 'none'` — bloquea plugins Flash/embed
- `base-uri 'self'` — previene base tag injection
- `form-action 'self'` — previene form hijacking a dominios externos
- `connect-src` — limita fetch/XHR a self + Supabase

## Punto 7 — Gestión Segura de Sesiones

### Middleware (`proxy.ts` → `middleware.ts`)

**Problema:** `proxy.ts` tiene el código correcto de Supabase SSR pero Next.js lo ignora — el archivo debe llamarse `middleware.ts` con default export `middleware`. Sin él, los JWT de 1 hora expiran silenciosamente aunque el usuario esté activo.

**Fix:**
1. Renombrar `proxy.ts` → `middleware.ts`
2. Cambiar `export async function proxy(request: NextRequest)` → `export default async function middleware(request: NextRequest)`

El código interno (session refresh + redirect si no hay user en `/dashboard/*`) ya es correcto.

### `InactivityGuard` — `components/InactivityGuard.tsx`

Client Component. Escucha eventos de usuario en `document`. Timer de 1 hora. Al expirar: `signOut()` + redirect a `/login?timeout=1`.

```
Eventos monitoreados: mousemove, keydown, click, touchstart
Timer: 3,600,000ms (1 hora)
Aviso previo: toast de advertencia 5 minutos antes (300,000ms antes del timeout)
Al expirar:
  1. await supabase.auth.signOut()
  2. router.push('/login?timeout=1')
```

Se renderiza en `app/dashboard/layout.tsx` como elemento JSX adicional (el layout sigue siendo Server Component — puede renderizar Client Components):

```typescript
// app/dashboard/layout.tsx
import InactivityGuard from '@/components/InactivityGuard'

export default async function DashboardLayout({ children }) {
  const user = await getUser()
  if (!user) redirect('/login')
  return (
    <>
      <InactivityGuard timeoutMs={3_600_000} warningMs={300_000} />
      {children}
    </>
  )
}
```

### Login — mensaje de timeout

`app/login/LoginForm.tsx` ya detecta `?logout=1`. Agregar detección de `?timeout=1` con mensaje diferenciado:

- `?logout=1` → "Sesión cerrada correctamente."
- `?timeout=1` → "Tu sesión expiró por inactividad. Inicia sesión nuevamente."

### Ciclo de vida de sesión

| Aspecto | Valor |
|---------|-------|
| Access token (JWT) | 1 hora — Supabase default |
| Refresco automático | En cada request vía middleware |
| Refresh token | Semanas — Supabase default |
| Timeout por inactividad | 1 hora sin eventos de usuario |
| Logout explícito | `supabase.auth.signOut()` — invalida sesión en servidor |
| Cookie flags | `httpOnly; Secure; SameSite=Lax` — seteado por `@supabase/ssr` |
