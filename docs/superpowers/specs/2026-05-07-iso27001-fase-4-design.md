## Objetivo

Implementar trazabilidad completa de acciones en el sistema: quién hizo qué, cuándo y desde dónde. Cubre login, logout, CRUD de todos los recursos, accesos a Drive y cambios de perfil.

## Sección 1 — Base de Datos

### Tabla `audit_log`

```sql
create table audit_log (
  id uuid primary key default gen_random_uuid(),
  usuario_id uuid references profiles(id) on delete set null,
  accion text not null,
  recurso text,
  ip_address text,
  user_agent text,
  created_at timestamptz default now()
);

alter table audit_log enable row level security;

create policy "admin_select_audit" on audit_log
  for select using (
    exists (select 1 from profiles where id = auth.uid() and rol = 'admin')
  );
```

- `usuario_id` nullable para loggear `login_fallido` (usuario no autenticado aún)
- Inserts exclusivamente via service_role client (server-side), bypasea RLS
- Sin política de INSERT via RLS — solo el servidor puede escribir

## Sección 2 — Helper `lib/audit.ts`

Helper server-only que resuelve automáticamente usuario, IP y user-agent.

### Tipo `AuditAction`

```typescript
type AuditAction =
  | 'login' | 'login_fallido' | 'logout'
  | 'acceso_drive'
  | 'crear_empresa'            | 'editar_empresa'            | 'eliminar_empresa'
  | 'crear_sucursal'           | 'editar_sucursal'           | 'eliminar_sucursal'
  | 'crear_usuario'            | 'editar_usuario'            | 'eliminar_usuario'
  | 'crear_chequeo'            | 'editar_chequeo'            | 'eliminar_chequeo'
  | 'crear_chequeo_pre_empleo' | 'editar_chequeo_pre_empleo' | 'eliminar_chequeo_pre_empleo'
  | 'cambio_contraseña' | 'cambio_correo' | 'cambio_nombre'
```

### Firma

```typescript
export async function logAuditEvent(
  accion: AuditAction,
  recurso?: string,
  usuarioId?: string   // solo necesario en login_fallido
): Promise<void>
```

### Comportamiento

1. Leer `x-forwarded-for` / `x-real-ip` de `next/headers`
2. Leer `user-agent` de headers
3. Si `usuarioId` no viene como parámetro, resolverlo via `supabase.auth.getUser()`
4. Insert via `createServiceClient()` — nunca falla la acción principal (try/catch silencioso)

### Nuevo archivo `lib/supabase/service.ts`

```typescript
import { createClient } from '@supabase/supabase-js'

export function createServiceClient() {
  return createClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!
  )
}
```

`SUPABASE_SERVICE_ROLE_KEY` existe en `.env`. Nunca importar `service.ts` desde un client component.

## Sección 4 — UI Admin

### Ubicación

`/dashboard/admin/ajustes/registros` — sub-ruta de ajustes.

En `AjustesClient.tsx` se agrega un nuevo `SectionCard` con ícono de log y un link/botón "Ver registros de auditoría" que navega a esta ruta.

### Archivos

```
app/dashboard/admin/ajustes/registros/
  page.tsx         ← RSC: lee searchParams, query Supabase, renderiza
  AuditTable.tsx   ← 'use client': filtros + tabla + paginación
```

### Filtros (via URL searchParams)

| Param | Tipo | Descripción |
|-------|------|-------------|
| `accion` | string | Valor exacto de `AuditAction` |
| `desde` | date string | `created_at >= desde` |
| `hasta` | date string | `created_at <= hasta` |
| `usuario` | uuid | `usuario_id = usuario` |
| `q` | string | `recurso ilike %q%` |
| `page` | number | Paginación offset (default 0) |

Cambiar filtro = push a URL → RSC re-fetches. Compatible con Back button, shareable.

### Query Supabase

```typescript
const PAGE_SIZE = 50

let query = supabase
  .from('audit_log')
  .select('*, profiles(nombre, rol)', { count: 'exact' })
  .order('created_at', { ascending: false })
  .range(offset, offset + PAGE_SIZE - 1)

if (accion)  query = query.eq('accion', accion)
if (usuario) query = query.eq('usuario_id', usuario)
if (desde)   query = query.gte('created_at', desde)
if (hasta)   query = query.lte('created_at', hasta + 'T23:59:59')
if (q)       query = query.ilike('recurso', `%${q}%`)
```

### Columnas de la tabla

| Fecha/Hora | Usuario | Acción | Recurso | IP |
|---|---|---|---|---|

- Fecha en formato local Nicaragua (`es-NI`)
- Acción con badge de color por categoría (acceso=azul, auth=verde, CRUD=gris, error=rojo)
- User-agent truncado con tooltip al hover

### Paginación

Server-side. Botones Anterior / Siguiente. Total de registros mostrado.

## Decisiones de Diseño

- **Service role para inserts:** audit log nunca es escrito por el cliente, solo por server actions. Elimina la superficie de ataque de políticas RLS de insert.
- **try/catch silencioso en helper:** fallo de logging nunca interrumpe la acción del usuario.
- **Open redirect protection:** `/api/drive-redirect` valida prefijo `https://drive.google.com/` antes de redirigir.
- **searchParams para filtros:** sin estado client, compatible con RSC, Back button funcional.
- **usuario_id nullable:** permite registrar intentos de login fallidos sin usuario autenticado.
